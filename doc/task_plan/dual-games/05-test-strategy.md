# 验证策略

- 所有执行在11700，测试DB与生产隔离；M1测试保留。
- UT先红后绿：S2.1文档/模板；S2.2探索状态；S2.3横版物理/机关。图形/声音适配代码在编辑前说明使用浏览器验证的理由，核心状态必须UT。
- 既有server/shared全量四项≥70%门槛保留；新增差异覆盖脚本对基线82c1c2d以来所有src TS/TSX新增可执行行计算UT命中比例≥70%，报告完整文件列表与未覆盖行，不能用E2E命中替代。
- 新行为通过UT+集成验证，纯视觉还需真实浏览器截图检查和输入测试；最终分别跑两玩法学生A创作→保存→提交→老师审核→学生B游玩到结局→反馈→作者修改。
- 游戏真实浏览器验证控制实际输入，不只注入完成状态；运行测试重开、失焦、返回编辑。屏幕取图在11700生成，Mac可查看结果。
- 关键命令：npm run typecheck / test:coverage / test:e2e / build / format:check；差异覆盖入口将在加入实现时建立。
- 每份证据记录时间、环境、命令、退出码、工作树源文件hash或commit。改动相关代码后旧证据失效。
- 真实学生与未获得的设备数据单独列未验证，不能标通过。

### 实际覆盖率采集
Vitest Node UT + Chromium组件/运行器UT共同生成V8报告，include全src TS/TSX，保留原server+shared总体四项70%与后端四项70%门槛（改为报告后聚合检查，统计范围不变）。浏览器UT直接挂载组件或运行器，不启动应用后端、不调用平台API、不访问数据库，与Playwright端到端分开。新增增量门禁按git baseline差异（含未跟踪文件）与Istanbul可执行行交集，缺文件报告直接失败，门槛70%。默认origin/main；整轮最终验收显式COVERAGE_BASE=82c1c2d48ddc79b33f0a6e6fef7e6a29e47d1510。

说明：首次全src报告75项UT通过，新增可执行行已过门槛；把旧client未测代码纳入报告后全局函数比例59.39%，这是原门禁统计范围扩大造成。保留全src报告，原server+shared门槛移至聚合脚本，没有排除新增业务文件；新增代码继续独立差异门禁，不用旧代码测试充高覆盖。
