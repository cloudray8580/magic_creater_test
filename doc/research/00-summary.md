# 当前调研汇总结论

- 调研日期：2026-09-26
- 项目：`magic_creater_test`
- 状态：研究结论与方向建议，产品需求和技术方案尚未由团队最终确认
- 阅读方式：先看本页，再按问题进入各专题；完整出处见 [来源索引](08-sources.md)

## 一、总体判断

**建议先验证“教师带领的创作与同伴互玩活动”，再决定是否开发完整产品及公开发行。** 核心体验是：选择可玩模板 → 自主改造 → 即时试玩 → 同伴认真体验 → 获得具体反馈 → 再修改。

这个方向具有创造性学习和动机理论依据，可能支持自主感、胜任感与归属感；本轮没有找到足以证明“学生创作关卡给别人玩，能够改善厌学或提高返校率”的直接高质量证据。它应当作为待验证的产品假设。

当前方案暂按 **12–15 岁、教师主持、电脑或平板、封闭小组、非医疗用途** 制定。这些是为了让方案可讨论的假设，尚不是团队确认的目标人群和使用场景。

## 二、帮助厌学学生：先明确问题，再选择干预

“厌学”可能指兴趣不足、学校倦怠、学习困难、焦虑拒学、抑郁、欺凌或家庭压力。业界与学术界通常组合使用自主支持教学、适配任务、心理干预、家庭工作、校园环境改善和家校协调返校；单一游戏不能覆盖所有成因。

基于游戏的心理干预确实存在，且已有公共采购和商业产品：

| 方案 | 主要对象与机制 | 成熟度与商业化判断 |
|---|---|---|
| SPARX | 青少年抑郁症状；RPG 中交付认知行为技能 | 有随机研究及新西兰公共服务历史；当前可用性需另核 |
| Lumi Nova | 儿童焦虑；游戏任务与现实暴露练习结合 | 部分英国 NHS 地区采用，NICE 早期价值评估仍要求补充证据 |
| Mightier | 情绪调节；心率反馈与游戏结合 | 有小型随机研究，家庭订阅和机构合作 |
| MindLight | 焦虑；暴露、注意训练和神经反馈 | 多项研究，结论依对照和报告者而异；本轮未核实广泛商业交付 |
| EndeavorRx | 特定 ADHD 人群的注意功能 | 美国处方数字治疗产品，不能推导为中国获批或厌学有效 |
| Scratch / Minecraft Education | 创作、表达、合作与学习参与 | 产品和教学生态成熟，特定心理疗效需独立验证 |

2024 年一项纳入 27 项随机试验、2,911 人的元分析发现，游戏化干预对抑郁和 ADHD 的平均效应较小，焦虑合并效应未显著。症状、出勤、创造力和课堂参与是不同结局，不应互相替代。[研究原文](https://pmc.ncbi.nlm.nih.gov/articles/PMC11420825/)

**产品含义：** 首期重点观察学生能否自主完成作品、是否愿意再次创作、是否获得平等反馈，以及教师能否组织活动。改善厌学、情绪或返校需要另行设计研究。

详见：[干预证据](01-interventions.md)、[游戏和活动方案](02-games-and-programs.md)。

## 三、Scratch：最值得借鉴的是创作与改编循环

Scratch 支持关卡、互动故事、动画、音乐、艺术和模拟等作品；“玩作品—查看内部—改编—运行—分享”让玩家和作者之间容易转换。模板、即时反馈、真实受众和同伴改编，比单纯增加素材数量更值得借鉴。

官方 2024 年报报告触达超过 1.4 亿用户、累计创建超过 10 亿个项目。这不是月活、公开作品数或疗效数据；当前不同官网页面的统计口径和更新时间也有差异。[官方年报](https://annualreport.scratchfoundation.org/)

当前编辑器主仓库采用 AGPL-3.0。代码、品牌、支持素材和社区作品的授权需要分别核验，不能认为“开源”就允许任意商业复用所有内容。[当前代码仓库](https://github.com/scratchfoundation/scratch-editor)

**建议顺序：** 先用纸面或合适的现成工具验证活动；确有上手、隐私或课堂管理障碍后，再决定改造 Scratch 或自研窄范围关卡工具。

详见：[Scratch 玩法、影响力和授权](03-scratch.md)。

## 四、中国大陆发行：先明确产品形态与渠道

主要门槛包括出版与运营主体、具体游戏审批、网站/APP 备案、平台测试或作品备案、实名防沉迷，以及 UGC、版权和未成年人数据管理。这些手续不能相互替代。

**对本项目影响最大的是课堂时段。** 如果产品被认定为面向未成年人的网络游戏，2021 年通知规定的周五、周六、周日及法定节假日 20–21 时服务窗口，会影响白天课堂使用。教育、免费、H5 或班级口令本身都不能作为自动豁免依据。[国家新闻出版署通知](https://www.nppa.gov.cn/xxfb/tzgs/202108/t20210830_666285.html)

| 路径 | 当前判断 |
|---|---|
| 内部原型、教师带领的受控离线活动 | 适合先验证体验；实际分发、内容、数据和校方准入仍需确认 |
| 校内局域网班级服务 | 可以支持互玩；需确认产品属性、网络和权限边界 |
| 公网 H5 或学校 SaaS | 浏览器和学校付费不能自动排除游戏、教育应用及数据监管 |
| App Store、安卓渠道、蒸汽平台等正式发行 | 按具体渠道准备资质、内容与运营体系 |
| TapTap 等平台测试、小游戏备案路径 | 官方存在条件化流程；不能外推为全部免费游戏免审批 |

作品分享还需要审核、举报、撤回、作者署名和版本追溯。首版建议由教师主持班级内互玩，优先保证反馈质量，暂缓陌生人社区与公开排名。

详见：[法规与渠道对照](04-china-release.md)。微信等部分渠道的最新后台材料仍待专项核验。

## 五、技术与部署：先做完整的小循环

若活动验证表明确有自研必要，建议首版限定为一种二维网格关卡，提供少量易懂组件、完整模板、拖放、撤销、即时试玩和作品导入导出。

| 层次 | 当前建议 |
|---|---|
| 界面与开发 | TypeScript + React + Vite |
| 二维运行器 | Phaser；先做目标设备兼容性验证，再锁定版本 |
| 规则创作 | 先做有限属性与事件；有需要后引入 Blockly |
| 作品存储 | 版本化 JSON、IndexedDB、显式文件导出 |
| 后续班级服务 | Fastify；单实例试点可用 SQLite，多校/多实例再评估 PostgreSQL |
| 部署演进 | 离线 → 学校批准的局域网服务 → 明确发行路线后的公网服务 |

作品使用受限数据和动作集合，不执行任意 JavaScript；编辑数据与试玩状态分开，重点保证撤销、存档、权限和异常关卡不会破坏课堂。

Mac 适合交互开发和设备调试；家里的 `i7-11700` 适合构建、测试、容器和班级服务模拟。学校课堂应使用批准的现场设备或正式服务，不依赖家庭电脑持续在线。当前没有完成实际产品性能测试，不能只凭硬件型号承诺班级容量。

详见：[框架、开发步骤与运维](05-technical-proposal.md)。

## 六、文档：Git 保存正式记录，协作文档承载讨论

建议保留仓库 `doc/` 作为研究、正式需求、架构和决策的权威位置；使用团队已有的钉钉文档/知识库组织讨论、会议和非敏感访谈总结。Agent 可以通过文件、Git、CLI/API 或已授权文档连接器参与。

每篇文档明确一个权威编辑位置：讨论形成结论后导出进入 Git；Git 中的正式规格在钉钉放链接或摘要。避免自动双向覆盖别人的修改。

**免费钉钉文档保留期限尚未取得统一官方承诺。** 正文、历史版本、回收站、聊天附件、空间额度和账号归属需要分别核验；不能把回收站恢复窗口解释为正文寿命，也不能承诺永久免费永久保存。正式成果应独立归档。

详见：[平台比较、Agent 协作与归档](06-documentation.md)。

## 七、建议的下一步与待确认事项

1. 明确首批年龄，以及“厌学”具体是兴趣下降、课堂参与少、焦虑拒学还是长期缺课。
2. 找到首个教师/学校伙伴，确认设备、活动时间、主持者和作品展示范围。
3. 先组织小规模纸面或现成工具创作活动，观察能否完成“创作—互玩—反馈—修改”。
4. 根据真实障碍决定是否自研，再做目标设备上的编辑、试玩、离线与存档探针。
5. 将已确认的产品决定写入 ADR；公开发行、医疗用途或生成式 AI 能力另立专项评估。

可直接讨论的 [试点与 40 分钟活动草案](07-pilot-and-open-questions.md) 已准备；[方向建议 ADR](../decisions/0001-proposed-direction.md) 当前仍是“建议”状态。本套调研没有替代团队作出最终产品决策。

### 本轮竞品补充
