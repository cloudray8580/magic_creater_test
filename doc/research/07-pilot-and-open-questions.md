# 07｜如何用小范围试点判断是否值得开发

日期：2026-09-26。以下为本项目建议的可行性方案，不是现成临床治疗方案，不声称这些样本量足以证明疗效。

## 1. 先把目标变成可观察的问题

| 假设 | 可以观察什么 | 不能偷换成什么 |
|---|---|---|
| 创作提供自主感 | 学生主动选择主题，能解释自己的决定 | 完成教师规定操作不等于自主 |
| 即时试玩提供胜任感 | 能发现问题、修改并看到变化 | 通关次数、老师代做不等于学生能力 |
| 同伴受众提供连接 | 学生收到具体反馈，并愿意回应或改进 | 点赞数量不等于归属感 |
| 体验可迁移到学习参与 | 学生更愿意在其他活动表达、合作或尝试 | 多玩十分钟不等于更愿意上学 |
| 活动可被老师持续交付 | 准备、故障、支持时间可接受 | 开发者全程救场不等于可推广 |

## 2. 分两步，不直接做疗效试验

### 第一步：形成性活动

建议邀请 6–10 名符合首批年龄范围、愿意参与的学生，做 2–3 次活动。可先用纸面关卡、积木或学校已批准的创作软件；由教师主持，开发者观察。这个数字是安排工作坊的建议，不是统计效能计算。

记录：最初是否愿意动手、卡在哪一步、哪些模板太难、谁需要成人代做、同伴反馈是否造成压力、是否有人不愿公开作品。用来修改产品，而不是出一张“有效率”海报。

### 第二步：多次活动可行性试点

建议在一个或两个小组开展 4–6 次活动，观察体验是否只来自新鲜感。若希望比较机制，可采用有序轮换：一组先创作互玩，另一组先参加时长相近、同样有老师关注的非数字创作活动，再交换；设计时考虑学习迁移、顺序效应和小组污染。

如要形成可发表的“改善厌学/返校”因果结论，应与教育和心理研究者合作，事先确定目标人群、主要结局、对照、样本量、随访、缺失数据处理和相应伦理审查，不能沿用这个小组规模宣称充分证据。

## 3. 一次约 40 分钟的活动草案

| 时间 | 学生活动 | 教师做什么 |
|---|---|---|
| 0–5 分钟 | 玩一个简单示例，任选主题 | 说明可以暂停、无需竞争、可以不展示个人故事 |
| 5–15 分钟 | 改一个模板，先做出可运行版本 | 提问“你希望玩家发现什么”，帮助拆小任务 |
| 15–25 分钟 | 自己试玩、撤销、调整 | 把失败解释为作品测试，避免替学生完成全部设计 |
| 25–33 分钟 | 两人互玩，每人一条具体反馈 | 确保每位作者被认真体验，制止嘲讽 |
| 33–38 分钟 | 选择接受一条建议或解释不接受的原因 | 尊重作者决定，帮助保存新版本 |
| 38–40 分钟 | 说一个自己的设计决定，导出作品 | 确认作品保存，明确活动结束与后续安排 |

活动主题可从“帮助朋友找到回家的路”“让同一关卡有两种解法”“设计一个让新手也能发现的机关”开始。不要强迫学生用作品披露创伤、家庭情况或诊断。

## 4. 评估指标：把过程、体验和迁移分开

### 过程与可用性

- 到第一次独立试玩需要多久；在约定活动时长内能否完成一个可运行作品。
- 教师帮忙次数及类型：设备问题、理解工具、设计困难或人际冲突。
- 是否发生丢档、打不开、同伴访问错误和无法停止的规则。
- 是否每个作品都获得一次公平试玩和具体反馈。

### 学生体验

- 自愿继续创作的意愿；是否觉得自己的选择被尊重。
- 是否能说出自己完成了什么、从反馈中改变了什么。
- 是否因比较、失败、公开展示或评论而不舒服。
- 短问卷应使用适龄、经讨论的措辞；自拟问卷只用于产品反馈，不能冒充临床量表。

### 现实迁移

- 教师与学生分别描述其他活动中的尝试、表达和合作是否改变。
- 如果未来纳入缺课/返校目标，使用实际学校记录与预先定义的出勤口径，结合情绪和功能结果一起判断。
- 有必要用标准化心理量表时，由专业伙伴选择有适用语言/年龄依据的版本、核验授权，并设计数据保护和异常结果处理。

没有一个指标可以独立支持“治好厌学”。停用人数、拒绝参与者、未完成者及负面体验都应纳入报告，不能只展示最喜欢游戏的学生。

## 5. 试点继续、调整和停止条件

以下是可以与教师共同确认的**产品决策条件**，不是医学阈值：

| 观察 | 后续决定 |
|---|---|
| 多数学生可以在支持下独立创作，第二次活动仍愿意参与 | 继续优化主循环，再扩大一点点规模 |
| 能玩但不会设计，主要由成人代做 | 降低编辑器门槛、加强半成品模板，暂缓社区 |
| 喜欢创作但不喜欢同伴展示 | 提供私密、双人或教师代展示选择，不强迫公开 |
| 老师组织成本或故障成本过高 | 优先改交付和可靠性，不增加新玩法 |
| 排名、评论或合作引发排斥和持续压力 | 暂停相关机制，调整分组和反馈方式 |
| 有严重痛苦、被欺凌披露或其他安全风险 | 按学校现有专业支持和转介流程处理，不靠产品自动诊断 |

## 6. 数据方案建议

可行性阶段尽量用观察表和本地作品；事件日志只记录必要的“创建、试玩、保存、分享、修改”等类别，不保存输入全过程、录屏或详细心理内容。若需要关联同一个学生，使用受控编号，并承认它仍可能是个人信息。

研究数据的保留时间由实际目的、学校要求和合法依据共同确定；不能随意写“全部永久保存”。到期删除应覆盖数据库、附件和备份轮换。项目仓库只保留去标识且经确认可分享的结论。

## 7. 接下来需要团队确认的事项

1. 首批年龄：小学、初中还是高中？是否混龄？
2. “厌学”具体指兴趣下降、课堂参与少、焦虑拒学，还是已长期缺课？
3. 谁主持：班主任、信息技术老师、心理教师还是专业咨询人员？
4. 一次活动多久、连续几周、每组多少人、学校有什么设备与网络？
5. 学生最想创造的是关卡、故事、音乐还是建筑？
6. 作品只给班级看，还是家庭/校外也能访问？
7. 是否有明确首个学校/机构伙伴，谁负责同意、数据和现场支持？
8. 团队接受 AGPL 和素材授权义务吗，还是需要完全自主的闭源商业产品？
9. 将来谁付费：学校、机构、家庭，还是公益项目？
10. 成功首先是完成作品、建立关系，还是改善出勤？最后一项需要更严格研究。

本轮已就年龄与试用场景向用户提出澄清，写作时尚未收到答案；当前技术建议使用 12–15 岁、教师带领作为可调整假设。任何答案变化都应同步更新 05 的范围和本章试点方案。
